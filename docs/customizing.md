# Customizing OVERTONE

OVERTONE is a static React and TypeScript site with no backend, so a fork is yours to reshape. This page lists the usual changes and the exact file and setting for each. After any change, run the checks in [Check your change](#check-your-change).

Start by getting it running locally (see [Run it locally](../README.md#run-it-locally)).

## Add your own example sound

The built-in examples are generated by code, not recorded, so they need no audio files and carry no licensing questions. Each example is a function that fills two arrays of samples (left and right) at 24 kHz for 12 seconds.

1. **Name it.** In `src/audio/types.ts`, add an ID to `DemoId`, for example `'doorbell'`.
2. **Describe it.** In `src/audio/demos.ts`, add an entry to `DEMOS`:

   ```ts
   {
     id: 'doorbell',
     name: 'Front door',
     subtitle: 'A conversation. A doorbell.',
     description:
       'Original generated example: two voices with a doorbell chime at 1.2 kHz. Reduce the chime to hear the voices clearly.',
     targetLabel: 'Find the doorbell',
     target: { startTime: 4.2, endTime: 5.6, lowHz: 1100, highHz: 1350 },
   },
   ```

   - Start `description` with "Original generated example" so visitors know it isn't a field recording. A unit test checks that every description contains the words "generated example".
   - `target` is the box the **Find the…** button selects: start and end in seconds, low and high in hertz. Use the spectrogram's hover readout to find good values. Keep it inside the 12-second clip, at least two frequency steps tall (about 24 Hz at 24 kHz) and at least one analysis window long (about 0.09 seconds), or the studio will refuse to apply it.

3. **Generate it.** In the same file, write a function `doorbell(left: Float32Array, right: Float32Array)` that adds samples. The existing `melody`, `pulse` and `drift` functions show notes, drums, hum, chords and chirps. Keep the peak below about 0.95 so it doesn't clip.
4. **Register it.** Add the function to the lookup in `createDemo`: `({ melody, pulse, drift, doorbell })[id](left, right)`.
5. **Test it.** The tests in `src/audio/engine.test.ts` automatically check every example for stereo output, the same result every time, a safe peak and loudness, the "generated example" wording, and a target that ends within 12 seconds. They don't check the target's size or frequency range, so add a test, modeled on the Glasshouse one, that applies your target and measures your sound dropping.

The example strip is laid out for three cards (`.example-options` in `src/styles.css`). With four or more, change `grid-template-columns` there, and add a `.sample-art-3` style if you want the new card's icon tinted differently.

To start the studio on a different example, change `'melody'` in three places in `src/App.tsx`: the `useState<DemoId | null>('melody')` line and both arguments of `loadClip(createDemo('melody'), 'melody')`. Several browser tests and `scripts/capture-media.ts` assume Glasshouse loads first (they press **Find the whistle**), so update those too.

## Change the limits

| Limit                           | Where                                                            | Default    |
| ------------------------------- | ---------------------------------------------------------------- | ---------- |
| Longest clip                    | `MAX_DURATION` in `src/audio/engine.ts`                          | 60 seconds |
| Largest file                    | `MAX_FILE_MB` in `src/config.ts`                                 | 30 MB      |
| Edits per clip in the studio    | `MAX_EDITS` in `src/config.ts`                                   | 12         |
| Edits per recipe in the engine  | `MAX_ENGINE_EDITS` in `src/audio/engine.ts`                      | 100        |
| Sample rates the engine accepts | `MIN_SAMPLE_RATE` and `MAX_SAMPLE_RATE` in `src/audio/engine.ts` | 8–96 kHz   |

`src/config.ts` gathers the studio's limits and re-exports `MAX_DURATION`. The import checks, on-screen limit text and error messages all read these constants. A few places still state the defaults in plain text and need updating by hand: the README, the [user guide](guide.md), and the browser tests in `tests/reliability.spec.ts` that expect "30 MB" and "60 seconds" in error messages.

Keep the limits compatible with the built-in examples. They are 12 seconds long at 24 kHz, so a `MAX_DURATION` under 12 seconds, or a sample-rate range that excludes 24 kHz, stops the studio from loading its first example. Keep `MAX_EDITS` at or below `MAX_ENGINE_EDITS`.

Longer clips use more memory and take longer to render on slower phones. The spectrogram also caps its detail at 720 time columns, so very long clips look coarser.

## Tune the processing

These settings change how the sound is analyzed and rebuilt. Read the [methodology](methodology.md) first, then change one thing at a time and listen.

| Setting                  | Where                                                       | Default       | Effect                                                                                                                         |
| ------------------------ | ----------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Transform size           | `FFT_SIZE` in `src/audio/stft.ts`                           | 2,048 samples | Bigger separates nearby pitches better but blurs timing. Smaller is sharper in time, coarser in pitch. Must be a power of two. |
| Hop size                 | `HOP_SIZE` in `src/audio/stft.ts`                           | 512 samples   | How far apart the analysis slices start. Keep it at a quarter of `FFT_SIZE` or less for smooth reconstruction.                 |
| Frequency edge softening | `Math.min(80, …)` in the mask code in `src/audio/stft.ts`   | Up to 80 Hz   | How gently a box's top and bottom edges fade. Wider is smoother but less precise.                                              |
| Time edge softening      | `Math.min(0.04, …)` in the mask code in `src/audio/stft.ts` | Up to 40 ms   | How gently a box's left and right edges fade in and out.                                                                       |
| Strength slider range    | The `reduction-range` input in `src/App.tsx`                | −3 to −60 dB  | The engine accepts 0 to −60 dB. To go further, change the bound in `validateEdits` in `src/audio/engine.ts` too.               |
| Isolate depth            | `kind === 'isolate' ? -60` in `applyEdit` in `src/App.tsx`  | −60 dB        | How much quieter everything outside an isolated box becomes.                                                                   |

The "widen the selection" check reads `FFT_SIZE`, and the downloaded recipe records both `FFT_SIZE` and `HOP_SIZE`, so they stay in step with your changes. The unit tests check reconstruction and attenuation at the current settings. If you change the transform size or hop, expect to revisit the thresholds in `src/audio/engine.test.ts`, and treat a failing reconstruction test as a real problem rather than a number to loosen.

## Change the look

- **Colors.** The core palette is the `:root` variables at the top of `src/styles.css` (`--text`, `--muted`, `--accent`, `--border`, `--surface`). Many other shades are written directly into the rules in `src/styles.css` and `src/components/spectrum.css`, so search both files for a color's hex value. [docs/design-system.md](design-system.md) gives an overview of the palette and the intent behind it.
- **Spectrogram colors.** `colorStops` near the top of `src/components/Spectrogram.tsx` maps quiet to loud, from near black through plum and orange to pale gold. Each stop is `[position from 0 to 1, red, green, blue]`. The display covers −96 dB to 0 dB of full scale.
- **Fonts.** `src/main.tsx` imports Space Grotesk and IBM Plex Mono from Fontsource, so they're bundled with the site. To swap one, install another `@fontsource/<name>` package, replace the imports, then update `font-family` and `--mono` in `src/styles.css` and the two matching `font-family` lines in `src/components/spectrum.css`.
- **Words.** Most on-screen copy lives in `src/App.tsx`, `src/components/InfoDialog.tsx` and the example descriptions in `src/audio/demos.ts`. Smaller labels are in `src/components/Spectrogram.tsx` and `Waveform.tsx`, and error messages also come from `src/usePlayback.ts`, `src/importAudio.ts` and `src/audio/engine.ts`. The browser tests and `scripts/capture-media.ts` find buttons by their labels (such as "Reduce selection" and "Export WAV"), so if you rename a button, search `tests/` and `scripts/` for the old label.
- **Page title and search description.** `index.html`.

## Deploy it somewhere else

The site is served from the `/overtone/` path because GitHub Pages hosts project sites at `https://<user>.github.io/<repository>/`.

**GitHub Pages under a different repository name:** change `base` in `vite.config.ts` to `'/<your-repo-name>/'`, then update the local address in `playwright.config.ts`, `scripts/capture-media.ts` and the `npm run dev` link in the README.

**Cloudflare Pages, Netlify or another static host at the site root:**

1. Set `base: '/'` in `vite.config.ts`, and change `/overtone/` to `/` in `playwright.config.ts` and `scripts/capture-media.ts`.
2. In the host's dashboard, connect the repository, set the output folder to `dist` and Node.js to version 24.
3. Use this build command. It also ships the font and library licenses with the site, as the GitHub workflow does in a separate step:

   ```sh
   npm run build && cp LICENSE THIRD_PARTY_NOTICES.md dist/
   ```

No environment variables or secrets are needed on any host.

## Check your change

```sh
npm test                        # signal-processing unit tests
npm run build                   # type check and production build
npx playwright install chromium # first time only
npm run test:e2e                # browser tests on desktop and phone sizes
npm run format                  # tidy formatting
```

If you changed anything visible, regenerate the README screenshots with the preview server running (`npm run preview` in one terminal, `npm run screenshots` in another), then look at the new images in `docs/media/` before committing.

## Ground rules worth keeping

These are what make OVERTONE trustworthy. If you change them, say so in your fork's README.

- Audio never leaves the browser: no upload endpoints, analytics or third-party scripts.
- Processing keeps the exact channel count and sample length of the input.
- The spectrogram is always calculated from the audio you hear, never painted on.
- Generated examples are labeled as generated.
